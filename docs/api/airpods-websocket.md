# AirPods 도우미와 웹의 로컬 통신

설계 제안 · 프로토콜 1.0 · 메시지 기준: [JSON Schema](helper-message.schema.json). 실제 Swift 도우미·장치 호환성은 아직 구현·검증되지 않았습니다.

## 연결과 인증

도우미는 루프백 주소의 선택 포트에서만 수신합니다. 실제 URI·ws/wss·인증서·HTTPS origin과의 연결 방식은 DEC-003 실험 후 확정합니다. localhost라는 이유로 브라우저가 연결을 허용한다고 가정하지 않습니다.

도우미는 허용 Origin을 확인하고 페어링 자격을 첫 `client.hello` 메시지로 검증합니다. 자격은 네이티브 도우미가 표시하는 일회성·만료 가능한 값으로 제안하며 웹은 메모리에만 둡니다. URL에 넣지 않습니다. 인증 전 센서 데이터 구독·송신은 거부하고 재연결도 인증합니다.

## 메시지 순서

| 방향 | type | 의미 |
|---|---|---|
| 웹 → 도우미 | client.hello | 버전과 페어링 자격 |
| 도우미 → 웹 | helper.ready | 새 stream_id, 실제 제공 주기, 모션 기능 가능 여부 |
| 웹 → 도우미 | clock.ping | 브라우저 단조 시계 t0 |
| 도우미 → 웹 | clock.pong | t0, 도우미 수신 t1·송신 t2 |
| 도우미 → 웹 | motion.sample | stream_id, seq, 도우미 단조 시각, pitch/roll rad, rotationRate rad/s |
| 도우미 → 웹 | sensor.status | 연결·모션·권한 상태. 착용 정보 미지원이면 unknown |
| 도우미 → 웹 | helper.error | 제한된 오류 코드. 센서 원본·토큰을 포함하지 않음 |

## 시계 정렬

웹 수신 시각 t3를 기록합니다. `offset = ((t1 - t0) + (t2 - t3)) / 2`로 도우미-웹 offset을 추정하고 `web_time = helper_time - offset`으로 변환합니다. 여러 왕복에서 지연이 작은 표본을 사용하고 불확실성을 유지합니다. 이는 로컬 전송 지연이 작다는 가정을 검증해야 하는 제안입니다.

재연결·절전 복귀·시계 역행·stream 변경 시 offset과 단기 버퍼를 폐기하고 재동기화합니다. 서로 다른 프로세스의 단조 시계 값을 직접 비교하지 않습니다. 순서가 역행한 sample을 과거 상태 덮어쓰기에 사용하지 않습니다.

## 품질과 복구

제안 입력 주기는 20Hz이며 실제 주기를 ready에 명시합니다. 브라우저는 이를 요구 정확도처럼 해석하지 않습니다. stale·seq gap·인증 끊김은 센서 품질로 처리합니다. 모션 지원과 오디오 연결·착용 추정을 구분합니다. 모션이 중단되면 웹캠으로 전환하거나 unknown이 됩니다.

OS pitch/roll 축·부호·회전 순서는 실측 전 가정하지 않습니다. 도우미는 원시 단위와 시각만 제공하고 웹의 분석 모듈이 승인된 축 프로필로 해석합니다. 원시 모션 메시지는 백엔드에 전달하지 않습니다. rotationRate의 ±100rad/s 범위는 전송 오류 차단용 제안 한계이며 판정 임계값은 정책의 별도 설정입니다.

유효·무효 예시는 [도우미 fixture](helper-contract-cases.json), 보안 요구는 [개인정보와 보안](../security/privacy-and-security.md)을 참고합니다.
