# 로그인 연결과 검증 범위

현재 로컬 개발은 루프백 전용 토큰을 사용합니다. 백엔드 설정 없이 프론트만 실행하면 카메라 미리보기만 가능합니다.
운영 후보인 Cognito 로그인은 설정했을 때만 켜지며 실제 사용자 풀·계정으로는 아직 검증하지 않았습니다.

## Cognito 설정

공개 클라이언트의 사용자 풀 ID와 클라이언트 ID, HTTPS API 주소를 빌드 환경에 설정합니다.
이 값들은 비밀번호가 아닙니다. 클라이언트 비밀키·개발 토큰은 프론트 환경 변수에 넣지 않습니다.
배포 빌드의 API는 HTTPS여야 합니다. 원격 화면에서 명시적인 루프백 주소로 인증 토큰을 보내는 설정은 거부합니다.
로컬 개발 화면과 로컬 API를 함께 쓸 때만 HTTP 루프백을 허용합니다. 일반 호스트명의 DNS 목적지는 이 검사 범위가 아닙니다.

| 환경 변수 | 값 |
|---|---|
| `VITE_AUTH_MODE` | `cognito` |
| `VITE_COGNITO_USER_POOL_ID` | Cognito 사용자 풀 ID |
| `VITE_COGNITO_CLIENT_ID` | 클라이언트 비밀키가 없는 앱 클라이언트 ID |
| `VITE_API_BASE_URL` | 배포 API의 HTTPS 주소 |

Vite 환경 변수는 빌드 시 반영하므로 값을 바꾸면 다시 빌드합니다. 현재 인프라 초안의 클라이언트는 SRP 로그인용이며
회원가입은 비활성화되어 있습니다. 테스트 계정 생성·이메일 확인과 실제 로그인은 담당자가 설정 후 검증합니다.

## 구현한 흐름

- 이메일·비밀번호 로그인, 임시 비밀번호 변경, SMS·이메일·TOTP 코드 확인, 비밀번호 복구.
- AWS Amplify Auth의 SRP와 토큰 갱신, 요청별 액세스 토큰, 사용자별 서버 기록 조회.
- 로그인 전 기록 차단, 로그아웃 시 이메일·기록 캐시·완료된 측정 상태 삭제, 진행 중 측정의 로그아웃 차단.
- 측정 중 인증이 만료되면 같은 계정으로 재로그인한 뒤 저장 재시도. 미전송 결과는 메모리에 남습니다.
- 실패한 시작 요청은 같은 계정의 재인증에서만 기존 식별자를 유지하며, 다른 계정으로 전환하면 초기화합니다.
- 계정 변경 전에 시작한 요청의 늦은 응답은 버리고, 대기 중인 재시도가 새 계정의 토큰으로 실행되지 않도록 차단합니다.
- 외부 주소로 로컬 토큰 전송 차단. 배포 빌드에 로컬 토큰이 들어가지 않는지 CI에서 검사합니다.

SDK의 액세스·갱신 토큰은 메모리에만 보관하므로 새로고침하면 다시 로그인합니다.
SDK는 진행 중인 로그인 단계의 임시 상태를 브라우저 세션 저장소에 보관하고 만료 시각을 둡니다.
MFA 최초 등록·관리형 로그인·회원가입과 실제 계정 연결은 별도 작업입니다.
브라우저 탭이 강제 종료되면 아직 서버가 승인하지 않은 측정 결과는 복원되지 않습니다.

## 확인

`npm run test:run --workspace frontend`는 SDK를 대체한 로그인·복구·계정 분리 검사를 실행합니다.
`node scripts/check-build-secrets.mjs`는 임시 검사용 토큰으로 배포 빌드를 만들어 토큰 포함 여부를 확인합니다.
가상의 잘못된 API 주소를 넣은 배포 빌드가 로그인 전에 차단되는 것을 로컬 브라우저에서 확인했습니다.
로컬 테스트는 실제 Cognito 발급·통신이나 운영 보안 검증을 대신하지 않습니다.
