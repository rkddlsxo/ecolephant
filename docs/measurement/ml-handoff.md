# ML 담당자 인계

## 맡을 작업

1. 브라우저에서 실행 가능한 자세 모델을 후보별 성능·속도·라이선스로 비교하고 선택합니다.
2. `frontend/src/features/measurement/model-adapter.ts`에 모델 로딩·영상 분석·리소스 해제를 구현합니다.
3. 각 프레임의 코·귀·어깨 위치와 신뢰도, 미검출·낮은 신뢰도·움직임 상태를 반환합니다.
4. 개인 기준 자세와 특징 변화·품질을 설계하고, 측면 기준 촬영과 참가자별 분리로 성능을 검증합니다.
5. 모델·실험 조건·데이터 동의·오차·누락률·환경별 결과와 실행법을 전달합니다.

## 프론트와의 경계

`PostureModelAdapter.load()`는 모델을 준비하고 `analyze(video, timestampMs)`는 결과를 반환합니다.
`close()`는 모델과 리소스를 해제합니다. 프론트는 카메라 권한과 영상 요소의 수명주기를 담당합니다.
반환값은 `cameraModelResultSchema`로 확인합니다. 이 형식은 모델 선정 전의 협업 초안입니다.

| 항목 | 형식 |
|---|---|
| `timestampMs` | 브라우저 단조 시계 기준 밀리초. 호출 시각을 사용 |
| `frameWidth`, `frameHeight` | 분석 영상의 실제 픽셀 크기 |
| `quality` | `valid`, `no_pose`, `low_confidence`, `motion` |
| `landmarks` | `nose`, `leftEar`, `rightEar`, `leftShoulder`, `rightShoulder` |
| 각 점 | 화면 원본 기준 0~1 좌표 `x`, `y`, 0~1 `confidence`; 없으면 `null` |

`valid`는 양쪽 어깨와 코 또는 한쪽 귀가 있어야 합니다. 낮은 품질은 정상으로 바꾸지 않습니다.
미러링은 화면 표시만 바꾸며 분석 좌표는 원본 기준입니다. 영상과 좌표는 기기 밖에 보내지 않습니다.

## 검증과 연결 조건

- 현재 카메라 특징은 CVA나 목 각도가 아닙니다. 검증 전 각도를 만들어 반환하지 않습니다.
- 실제 데이터 저장 전 모델·품질 기준·정책을 검증하고 DEC-002/007을 팀에서 결정합니다.
- `data_source=real`은 승인 정책이 필요하고 카메라를 쓰면 검증된 매핑도 필요합니다. 현재는 차단됩니다.
- 정책은 불변 버전으로 등록해야 합니다. 초안의 승인 플래그만 바꾸거나 합성 판정식을 그대로 실측에 쓰지 않습니다.
- 백엔드가 새 정책 ID와 세션별 기준을 보존하지만, 프론트에 새 정책을 전달하고 사용하는 기능은 아직 없습니다.
- 모델 결과를 현재 파생 결과 계약으로 변환하는 방식과 실측용 판정은 모델 검증 후 팀에서 함께 구현합니다.
- 동일 참가자의 프레임은 학습·평가에 섞지 않습니다. 조명·거리·회전·가림·미검출을 포함합니다.
- 측면 CVA와 머리 기울기는 서로 다른 값입니다. 같은 지표를 추정하는 경우에만 각도 오차를 비교합니다.
- 10~15명은 예비 실험 제안이며 성능 목표·표본·판독 방법은 결과를 보기 전에 정합니다.
- AirPods 센서 수집·축·연결은 별도 담당과 협의합니다. 이어버드 데이터가 웹캠 모델의 필수 입력은 아닙니다.
