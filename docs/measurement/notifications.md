# 지속 자세 알림과 교정 기록

수치는 원문 시작값이며 [예시 정책](../../backend/harness/fixtures/policy/example.json)에 모았습니다. 알림 빈도 자동 감소의 구체 알고리즘은 DEC-007 결정 전 사용하지 않습니다.

## 조건과 단계

| 단계 | 조건 | 처리 |
|---|---|---|
| 화면 주의 | caution | 색·문구 갱신. head_flexion 예외 외 일반 알림 없음 |
| 후보 | high 또는 결합 모드에서 head_flexion이 30° 이상 | 유효 연속 시간 누적 |
| 1차 | 후보 20초 지속 | 화면 강조, 허용한 채널의 알림 시도 |
| 2차 | 전달된 1차 뒤 30초 동안 후보가 지속 | 구체 행동 문구 1회. 새 에피소드로 세지 않음 |
| 쿨다운 | 1차 뒤 5분 | 같은 에피소드의 2차를 제외한 새 알림 억제 |

쿨다운을 1차 전달 시점부터 세고 2차만 허용하는 것은 설계 제안입니다. 전달된 채널이 없으면 교정 효과 표본을 만들지 않습니다. 알림 시도 실패도 기록하되 같은 프레임에서 무한 재시도하지 않습니다.

## 중단과 교정

- 알림 후보가 해소되거나 품질이 무효, 모드·보정이 변경되면 연속 후보 시간을 초기화합니다.
- 교정은 알림을 발생시킨 조건이 연속 3초 해소된 경우로 제안합니다. 시작 시각은 해소 구간의 첫 시각입니다. 이 3초는 실측·팀 합의 대상입니다.
- 다른 자세 문제가 남아 있으면 ‘전체 자세 정상’으로 표시하지 않습니다.
- 교정 관찰은 1차 전달 후 최대 120초로 제안합니다. 종료·무효·관찰 만료이면 결과를 unknown으로 닫고 0초 교정으로 넣지 않습니다.
- 재알림, 사용자 음소거, 알림 권한 거부, 탭 중단을 각각 구분합니다.

## 채널

화면 토스트·테두리는 기본 채널입니다. 시스템 알림은 사용자 동작으로 권한을 요청하고 실제 브라우저 지원을 확인합니다. 소리는 사용자가 켠 경우에만 실행합니다. AirPods 착용만으로 브라우저 출력 장치를 AirPods로 보장하지 않으며 현재 OS 출력 장치 안내를 제공합니다.

이벤트의 `result=delivered`는 브라우저 API 또는 화면 렌더링에서 실행을 확인했다는 의미입니다. 사용자가 실제로 보거나 들었다는 증명은 아닙니다. 여러 채널은 같은 alert_id를 공유하고 교정 지연 표본은 중복 집계하지 않습니다.

웹이 백그라운드에서도 계속 측정·알림할 수 있는지는 DEC-010 검증 대상입니다. 수집이 멈춘 구간의 알림을 보장하는 문구를 쓰지 않습니다.
