# Flask 결과 저장 API

Python 3.12 · Flask 3.1 · Waitress 로컬 서버입니다. 저장소 루트에서 `npm run setup`, `npm run dev`로 시작합니다.
기본 프론트 허용 주소는 `http://127.0.0.1:5173`입니다. 기존 환경 파일은 자동으로 바꾸지 않습니다.

## 구조

| 모듈 | 책임 |
|---|---|
| `ecolephant/__init__.py` | 앱 생성·설정·요청 한도·안전한 오류 |
| `auth.py` | 로컬 데모 토큰, 배포용 Cognito JWT 검증 경로 |
| `contracts.py` | OpenAPI 요청 검증·파생 신호 일치 확인 |
| `policies.py` | 정책 형식 확인·세션별 불변 기준 보존 |
| `routes.py` / `service.py` | 12개 HTTP 동작·멱등성·연속성·종료 |
| `storage.py` | 기본 SQLite 트랜잭션 저장 |
| `dynamo.py` | DynamoDB Local 검증 어댑터, 실제 AWS 환경 미검증 |
| `metrics.py` | 시간 가중·방식별 집계·타임라인·시간대 버킷 |
| `contracts/` | 정식 명세에서 생성한 런타임 복사본 |

## 운영 경계

- 기본 실행은 루프백 전용이며 무작위 로컬 토큰을 사용합니다. 일반 사용자 로그인은 아닙니다.
- Cognito 로그인 연결과 JWT 검증은 시험용 키와 모의 객체로 검사했습니다. 실제 사용자 풀과 계정 검증은 남았습니다.
- health 이외 API는 소유자 인증이 필요합니다. 서버는 본문 owner_id를 받지 않습니다.
- 완성된 동일 배치는 중복 승인하고, 내용이 다른 식별자·종료 누락은 409로 거부합니다.
- 연속 배치는 세션의 집계 상태를 원자적으로 갱신하고 이전 결과를 반복 조회하지 않습니다.
- 순서 변경·중복·이전 형식·알림 경계는 전체 검증으로 돌아가며 동일한 승인 결과를 유지합니다.
- 상세는 세션 정보만, 이벤트 목록은 이벤트만 조회합니다. 분 경계 타임라인은 분별 요약을 읽습니다.
- 비정렬 타임라인·이전 기록·요약 누락은 원본 결과로 계산합니다. 통계와 이벤트 저장은 전체 결과를 읽을 수 있습니다.
- 이전 SQLite 버전으로 되돌리기 전에 `timeline_buckets`의 삭제·정리 경로를 포함한 마이그레이션을 준비해야 합니다.
- DynamoDB Local 3.3.2에서 동일 API 흐름·최대 60개 배치·충돌과 실제 행 삭제를 확인했습니다.
- DynamoDB 삭제 재시도는 이벤트 ID가 다른 세션으로 재사용됐는지 확인하고 해당 세션의 식별자는 지우지 않습니다.
- 현재 정책은 실측 미승인입니다. `real`은 승인 정책과 카메라 사용 시 검증된 매핑이 필요합니다.
- 세션은 생성 당시의 정책을 보존하며 동일 ID의 다른 내용은 거부합니다. 예전 초안 세션은 고정된 원본 기준으로 읽습니다.
- 테스트와 실측은 출처별로 통계를 분리합니다. 현재 제공된 정책으로는 실측을 저장할 수 없습니다.
- 영상·관절점·원시 IMU 필드는 폐쇄된 요청 스키마에서 거부합니다. 요청 원문을 오류·로그에 반사하지 않습니다.
- 요청 처리 후 `request_id`, `method`, `path`, `status`, `latency_ms`, `owner_hash`, `error_code`만 한 줄 JSON 로그로 기록합니다. 원본 데이터와 토큰은 로그에 남기지 않습니다.
- 삭제는 결과·이벤트를 제거합니다. 지연된 생성 재시도로 복원되지 않도록 불투명 식별자 tombstone만 유지하며 보관 기간은 DEC-006에서 정합니다.
- 배포용 Lambda는 Cognito 설정 없이는 시작하지 않습니다. 로컬 토큰으로 배포되는 것을 차단합니다.

## 새 정책 연결

팀 검증 후 새 ID의 JSON을 `ecolephant/contracts/policies/`에 추가하면 서버 시작 시 형식을 확인합니다.
기존 초안·과거 정책의 ID나 `legacy-policy.json` 내용은 변경하지 않습니다. 정책 원본은 DB에 계속 남습니다.
현재 프론트는 합성 테스트용 초안만 사용합니다. 새 정책 전달·실측 변환은 ML과 프론트 연동 및 계약 변경이 필요합니다.
승인 플래그만 바꾸는 행위는 검증이 아닙니다. 긴급 승인 취소·기존 세션 차단 절차도 운영 전에 별도 결정해야 합니다.
